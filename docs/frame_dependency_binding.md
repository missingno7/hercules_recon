# Applying the Blood2 linkage lesson

The first frame-family experiment corrects seven reference identities in the
bootstrap source. Four callers now use recovered configuration/defaults and
allocator/cancellation providers. Three count references now use the same observed
cell names as the configuration writer. The allocator and cancellation declarations
also agree with the recovered providers' return views; historical names and full
prototypes remain unproved.

Each old/new identity was checked against the same ENG1 oracle hash and RVA.
Fresh baseline, private candidate and independent canonical compilation preserve
all three code contributions (304, 272 and 832 bytes). Ordered relocation offsets,
types and unmodified names remain identical; only the seven reviewed reference
names change. Bootstrap remains relocation-only equal; cleanup and setup retain
their previous non-reference differences. No new `FUNCTION_MATCH` is claimed.

The synthetic bootstrap fixture now links actual configuration and allocator/
cancellation forwarding units alongside its existing real lifecycle wrappers,
chain bridge and accepted chain writer. Its 193 checks exercise configuration
selection flowing into allocation sizes, count changes across allocation calls,
live-context defaults, cancellation, cleanup order and setup. Remaining local
dependencies, host callbacks and storage are explicit observing fixtures. These
synthetic providers are not used by the natural link diagnostic.

The natural diagnostic link uses eight actual source units and the pinned
experimental VC5 CRT. The old source yields 121 unique unresolved names; the
corrected source yields 114. Four callable references acquire actual definitions.
Three count aliases collapse into already-unresolved configuration names; the
observed cells still lack production data definitions. Neither run has duplicate
source definitions. The link remains incomplete and its CRT variant and historical
unit ownership are unproved.

`scripts/dependency_link.py` and `evidence/frame_link_plan.json` make this a regular
bounded diagnostic. The script checks frozen complete contribution identities,
source/header/specification provenance and oracle hashes, validates the accepted
writer afresh, and writes unique reports under ignored `work/`. It never loads the
linked image or modifies recovery state. A link with unresolved symbols is a
successful diagnostic run, not a successfully linked module.

Next work should recover actual missing local bodies and data owners from this
report, distinguishing selected-family omissions from genuine missing source.
Do not rewrite relocation-only equals to manipulate layout or invent empty
production definitions to remove link errors. Reference evidence and validation
are recorded in `evidence/frame_dependency_binding.json`; `recovery.json` remains
the sole accepted state.
