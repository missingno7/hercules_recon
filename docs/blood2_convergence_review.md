## Highest-value transfer: link real dependency families

Blood2's natural links exposed caller/definition prototype disagreements, duplicate
owners, invented aliases for structure members, wrong imports, missing library
contributions, and dependencies introduced by a later-engine seed. Correcting these
also unlocked matching functions. Its reported Server milestone links 76 canonical
objects with zero unresolved symbols and zero duplicate definitions. Earlier links
using four private candidate objects were explicitly distinguished from canonical
closure. Even the experimental images had zero functions at native RVAs: successful
linkage was not whole-image equality.

[canonical Server milestone](https://github.com/missingno7/blood2_recon/commit/345e7ee48b3b8c9250e1ff908d81cf2d75823db5).

Hercules already has `scripts/host_pool_full_linkage.py`. Extend that pattern to the
frame/bootstrap/configuration family before another source-form search on its

inventing production stubs or forcing placement. In particular, reconcile the

configuration functions, the count globals with their observed cells, and allocator

observed address are evidence to investigate, not permission to merge identities.
Any source/header change still needs fresh measurement and protected-peer checks.

## Recover compilation context from positive evidence

Recent Blood2 gains involve correct helper ownership, header inlines, caller shapes,
and genuine source inventories. Nine Intel renderer units changed flags only after
native argument setup was compared against known compiler anchors and two images.
That flag commit itself reported no strict gain; later source/context changes did.

Source: [native call-argument evidence](https://github.com/missingno7/blood2_recon/commit/fc11559c37b4e271e8406b03f950307f8535991b).

For Hercules, use several already-exact VC5 anchors to predict a specific compiler
or ownership effect, then test a coherent family. Do not transfer Intel options to
VC5 or enumerate flags blindly. Preserve complete contributions and declared
header context when moving helpers or correcting shared declarations.

## Prefer observed live reads over decompiler temporaries

Blood2 reports that direct reads through owning objects recovered model helpers
where cached view-pointer locals changed register allocation. One animation search
re-read its member across `stricmp`; four additional helpers gained from direct
member forms and an attested header inline. A separate local success lost strict
functions through a shared constant-pool binding, which the full builds caught.

Source: [structural findings](https://github.com/missingno7/blood2_recon/blob/00a56bd63ab4d155c28efb2a9a9d38be3a0fde18/recon/experiments/opus-structural-1/engine_findings.md).

Apply this as a targeted discriminator wherever PC instructions reload global or
member state across a call. Our close-state protocol already models live context
reloads. Extend that discipline to remaining families when instruction evidence
supports it; do not turn it into a blanket rewriting rule.

## Strengthen ancestry and library evidence, without importing later behavior

Blood2 can exploit released sources and unstripped sibling binaries for names,
unit inventories, declaration order, inlines and historical version differences.
Its later AVP2-shaped warp seed introduced dependencies absent from Blood2; backing
it out removed those dependencies and yielded matches. Hercules has a weaker
source-ancestry starting point, so this is a method to transfer, not a comparable
expected rate of progress.

Keep dated PC/library evidence primary. Use PSX and later SDK material to generate
bounded hypotheses; distinguish compatible layouts from historical type identity.
Investigate omitted genuine dependencies rather than adding declarations merely
to move the compiler's internal state.

## Compact context is useful, but secondary to dependency recovery

Blood2 caps warm receipts and shares repeated facts by identity while preserving
their full decoded content. This is useful as Hercules's peer-context receipts
grow. Any future compaction must preserve predictions, falsifiers, negative family
results, input provenance, and full output identities. Derived caches must remain
disposable and outside acceptance. Do not import model difficulty scoring, an
automatic scheduler, declaration-padding searches, or routine model review.

Source: [workflow](https://github.com/missingno7/blood2_recon/blob/00a56bd63ab4d155c28efb2a9a9d38be3a0fde18/docs/WORKFLOW.md).

## Proof boundary

Blood2's `EXACT_MATCH` and `FUNCTION_MATCH_STRICT` compare bytes apart from relocation
fields and validate referenced addresses, imports, literals and cross-object
bindings. This is substantially stronger than masked similarity, but differs from
Hercules's complete raw target-byte equality after fresh historical compilation.
Adopt reference-binding checks as additional diagnostics; do not convert their
classification into our `FUNCTION_MATCH` or relax our gate. Natural linkage,
function matching, source coverage, module layout and whole-image equality remain
distinct claims.

Source: [verifier definition](https://github.com/missingno7/blood2_recon/blob/00a56bd63ab4d155c28efb2a9a9d38be3a0fde18/scripts/engverify.py).

Recommended order: frame-family natural linkage and ownership reconciliation;
evidence-backed TU/header recovery; targeted live-read hypotheses; then context
compaction if receipt size is materially obstructing those tasks. Existing raw
acceptance and regression requirements remain unchanged.
