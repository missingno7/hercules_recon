reproducing the original game. A faithful modernized game should grow from
recovered game logic and interfaces. Behavioral source, renderer work, REA and
emulation resolve the same implementation. Architecture follows evidence;
successful previews and finite comparisons retain their stated proof limits.

## Experiments into matching progress

Use one cycle: original-backed question → bounded experiment → supported source
or dependency correction → fresh historical comparison and protected-peer
regression. Only normal raw acceptance changes `FUNCTION_MATCH`. A successful
natural link proves dependency closure within its inputs, not original placement.
Masked equality and finite behavior remain separate claims.

Concrete feedback already available:

- REA's `0x79A0` lead is independently re-derived by the
  [idle-owner audit](../renderer_contract/callback_metadata.md). Use the actual
  MFC `OnIdle` ABI and SEH/entry relationships in host recovery. Pseudocode must
  not determine calling conventions or replace source.
- [Frame pacing](../renderer_contract/frame_pacing.md) ties the existing
  `host_timing_dispatch_5f20.c` to idle delivery and render-skipping catch-up.
  Reuse that source rather than building another scheduler or inferring time from FPS.
- [Renderer closure](../renderer_contract/closure.md) and producer fixtures expose
  live-link reloads, field widths, transitive reads and independent writers.
  These discriminate original routines and declarations; a modern rasterizer
  cannot be promoted as historical source.
- [Host recovery](host_runtime_reconstruction.md), actual archive/PCM pipelines
  and behavioral module graphs already supply useful providers. Close missing
  bodies, storage owners and libraries before repeating equivalent source forms
  or building another resource loader.

The function-map alignment filter is not a complete census or evidence of /Gy.
`--include-unaligned` exposes additional address-backed leads without changing
default inventories or recorded extents. Loader-zero storage does not imply
file-static C or a C++ definer: a fresh pinned C control emits an external
explicit-zero definition in `.bss`. `unit_bounds.py` reports conditional clusters,
not historical TU boundaries.

## Renderer choice and next work

| Path | When valuable | Current decision |
| --- | --- | --- |
| A. Continue the drop-in | A specific original-host observation or integration experiment answers a reconstruction question | Keep the tested seam; defer fullscreen takeover and broad feature work |
| B. Integrate into the reconstructed game | Genuine game/host source and resource/state lifetimes provide a stable caller | Prefer this simplification if closure supports it; do not design an adapter hierarchy in advance |
| C. Keep drop-in as research | Measurements and fixtures remain useful after interception is unnecessary | Best present role; retain knowledge while allowing deployment code to retire |

These can be successive stages. Keep recovered game logic free of modern API
dependencies and build modern platform/rendering code separately against
supported interfaces. Share evidence and algorithms where appropriate. Current
directories, borrowed packet events and DLL hooks are not permanent engine
boundaries. Movie/text/palette/clear/mode/presentation ownership is separate from
slot-89 interception. Native-resolution geometry needs upstream association.

Prioritize **one coherent original dependency family at a time**. Select real
missing contributions from current TITLE/ENG1/host graphs, compile complete
supported units, preserve exact peers and attempt natural linkage. Use REA or
rendering experiments when they discriminate a shared uncertainty in that family.
This takes precedence over new GPU effects, routing frameworks or blanket
source-form searches. An owned renderer event bridge remains a possible future
implementation, not the next mandatory project milestone.

Original post-entry work retains authorization, write/profile/registry isolation,
windowed startup and restoration requirements. No new game process ran here.
