# Parallel LLM matching wave

Base `fd6421d`: 24 disjoint Luna xhigh matching lanes covered 42 function targets,
with four additional Options reference lanes and one bounded Sol high shared
blocker investigation. Native subagents received focused packets, private scratch,
explicit source/symbol ownership, at most four compiler calls and 6,000 tokens per
matching lane. No full-history forks or new scheduler/routing database were used.
Root alone reviewed references, changed the ledger and ran protection gates.

The host exposed 32 logical processors and about 63 GiB to the runtime. An
8-job/24-job pinned-compiler isolation probe passed all 32 complete RAW controls,
with unique object paths and equal unit inventories. Throughput was 13.38/14.12
compiles per second; more LLM workers primarily parallelize reasoning, not compiler
speed. This is a capacity check, not a reconstruction-coverage claim.

## Cost and process corrections

Luna matching lanes reported **17 focused compiler calls**; the shared Sol probe
used 3. Six accepted functions / 272 B corresponds to 35.3 functions / 1,600 B
per 100 focused Luna calls, or 30 functions / 1,360 B including Sol. This harvest
of existing source is not comparable to a missing-behavior campaign or a permuter
search. Model-token totals were unavailable.

End-to-end accounted compiler executions were **585**: 20 focused/shared, 32
capacity controls, 245 successful strict protection, 122 in a rejected integration,
108 linked protection, and 58 test fixtures across two suite runs. End-to-end
yield is 1.03 accepted functions / 46.5 B per 100 calls. That is not evidence of
an overall speedup: integration/development overhead still dominates. No expensive
all-module source build was repeated for these unchanged-source promotions.

The rejected integration exposed a real existing gate limitation: unchanged units
had size-exact reconstructed neighbors, and their pinned helper inventory also
listed already accepted RAW neighbors. The opt-in preservation path now validates
the former's recorded full compiled contributions and still freshly proves every
accepted RAW/RELOCATED/LINKED peer. No instruction/reference comparison was relaxed.
Both successful batches reused one compile per profile inside their fresh gates:
122 calls / 500 rows / 48.632 seconds, then 123 / 502 / 47.405 seconds.

Indexed worker packets also pointed at removed `calibration/` paths. `region.py`
now resolves reviewed migration mappings and current ledger ownership. Split units
are listed explicitly with source hashes and symbol aliases, no merged baseline
and no reused frontier receipts. Ambiguous/missing ownership fails closed. This
prevents each worker rebuilding that context manually. Restart completed workers
with `followup_task`; `send_message` alone only queues a notification.
