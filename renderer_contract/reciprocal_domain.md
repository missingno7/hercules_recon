# Reciprocal and edge-step boundary findings

The original PC image has two observed paths for bounded edge steps. D60C indexes an initialized 2,048-entry reciprocal table and applies signed 32-bit `IMUL` followed by `SHRD EAX,EDX,30`. C2E0 instead applies `SHL EAX,16`, sign extension with `CDQ`, and signed `IDIV`. The finite probes pin their extent guards and the arithmetic results near `0x800`; they do not establish a general rasterizer contract.

The probe receipt is [native_reciprocal_domain.json](evidence/native_reciprocal_domain.json) (`BOUNDED_OBSERVED`; runner `BOUNDED_ORIGINAL_BYTES`): 12 isolated original-byte fixtures, each capped at 250,000 instructions, and 24,576 table-formula comparisons. The initializer at HERCULES.EXE RVA `0x72a0..0x72cc` writes `R[0]=0`, then `R[i]=floor(2^30/i)` for `1..2047`. The independent formula matches every initialized entry in each fixture. The native module identity is SHA-256 `587ae2e90fd2d1827dab6a2745340240e500846f974f718278e2a50199769c1d`.

The pre-run prediction that screen clipping prevents a D60C width-2047 span lookup was falsified. The `d60c_xspan2047_pre_crop` case reaches the lookup for `R[2047]`, then a clipped row loads `R[1023]`; its bounded visible output is 638 pixels across two rows. Width 2048 takes the signed extent guard before any reciprocal lookup. Width zero skips the span reciprocal lookup, though edge reciprocals can still be read. Thus the accepted positive extent domain is below `0x800`, but screen clipping does not cap the pre-crop table input at 319.

For D60C `dy=0`, there is no edge lookup. `dy=2047` reads `R[2047]=0x80100` on both edge paths; `dy=2048` takes the guard before lookup. The captured edge operations match a signed 64-bit product followed by logical `SHRD 30`: for `(delta,R)=(+131072,524544)` the result bits are `0x40`, and for `(-131072,524544)` they are `0xffffffbf`. The accepted wide X-edge sample `(-134152192,536870912)` produces `0xfc008000`. These results are finite operand checks, not proof that all input values follow that formula.

C2E0 `dy=0` returns without IDIV; `dy=2047` reaches two signed IDIVs with dividends `+131072` and `-131072` and divisor `2047`, producing observed `(quotient,remainder)` pairs `(+64,+64)` and `(-64,-64)`. Its `dy=2048` extent takes the guard before IDIV. A separate accepted edge with `deltaX=-2047` generates dividend `-134152192`, still representable as signed 32-bit after `SHL 16`, and divides by 2 to `(-67076096,0)`. `deltaX` extent 2048 takes the guard before division. No generic wrap or divide-fault behavior is inferred outside this guarded domain.

Static byte pins and selected instructions are in the machine receipt. Relevant code spans are initializer `0x72a0..0x72cc` (SHA `3d59be43f3756224228dfdcc372a3bc59b7a7dbba4bbab8c79dd821cc958014b`), D60C `0xd60c..0xdd70` (`2ed9dc4341703ee82f789528b427f6333e6d916bec11148fe2cfecff14119b4a`), CC50 `0xcc50..0xd415` (`7504054c2fe867eef6602dbd439f1972b55a73540b98099498772db2f34b7fd0`), DD70 `0xdd70..0xe675` (`2d13dbe76315a0e9e0b2fbec9fc1d84beffc377ee8df2988a6f1f354329cf9be`), E680 `0xe680..0xef60` (`f42bfcb06d042a8cd9ced6a8df5375b734c1e5641811a062059bbd02cb8dcb58`), and C2E0 `0xc2e0..0xc6f8` (`a48b74f8f7a2f963645d3632a5333dac956aebc9143ba73acaa12b911e3b6903`). CC50, DD70, and E680's mask/load/guard sites are static observations only; no matching dynamic executions were performed for them.

The public arithmetic helpers are `hercules_edge_steps.[ch]`, with `tests/test_edge_steps.c` and `tests/test_original_reciprocal_domain.py`. They use shared fixed-width typedefs and size checks, with C++ linkage guards. The D60C helper takes the captured Q16 delta passed to IMUL, rather than a raw coordinate difference. The integrated VC5 and GCC64 suites each pass its 27 checks; [verification.json](evidence/verification.json) and [portable_verification.json](evidence/portable_verification.json) pin sources and compilers. Arithmetic model checks remain separate from bounded original execution.

The runner retains `BOUNDED_OBSERVED` / `BOUNDED_ORIGINAL_BYTES` labels; its fifteen asserted properties apply only to the named finite cases. The C helper is a separate arithmetic model. Original game files, assets and recovery evidence remain unchanged.
