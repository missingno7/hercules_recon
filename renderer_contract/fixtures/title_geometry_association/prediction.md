# TITLE mode-5 geometry association experiment

## Prediction

Against the hash-pinned original TITLE.DLL producer at RVA `0x181e0`, an explicit synthetic caller/context that satisfies only the producer's required state will expose four source-point roles at the actual native callback boundary: batch input roles 0–2 will pass through slots 102/107 and be copied by slot 117 to FT4 corners 0–2; the fourth single-point role will pass through slots 101/106 and be copied by slot 114 to corner 3. The source triplets may coincide because the producer can reuse or degenerate local coordinates; identity is the role plus the callback-time input pointer/value and route, never screen-space equality. The resulting FT4 record will use the producer's 0x28-byte stride, carry the mode-5 command/texture fields written by that producer, link through the selected order-table head, and advance/publish its pool cursor as the unchanged producer dictates. I will not assume world units, a general object identity rule, camera interpolation, or visibility outside this constructed caller.

The prediction is falsified by any producer input/callback order that does not match those four point identities, any point-to-corner mismatch, any texture/command/link/cursor field that disagrees with the original producer trace, an unaccounted native write, or an execution path that requires an unknown callee/data/callback value to be invented as successful. If bounded initialization reaches an unknown dependency, that exact PC/dependency remains unresolved and the candidate must stop there.

## Finite case plan

The first candidate stream `[10,20,0,1,2,3,4]` is a closure probe only. The stream discriminator `[10,20,0,7,13,21,29]` changed X values but falsified the four-distinct-triplets hypothesis: the producer constructed `[36,62,0]`, `[92,62,0]`, `[36,62,0]`, `[92,62,0]`. Object flag bit `0x10` selects an additional signed-byte coordinate path at `TITLE+0x18385`; setting it (`flags=0x94`) changed the X signs but retained paired duplicates. Setting object bit `0x40000` and word `+0x26=8` shifted the common Y lane uniformly, so it also did not produce four distinct tuples. Byte2=`0x80` entered the high-bit branch but its masked payload was zero, leaving packet UV unchanged. Final proof therefore does not require numeric uniqueness: it records four callback-time source roles, their actual pointer and signed-WORD values, and the native producer's exact batch/single routing to packet corners. For the final differential, keep camera/object/other stream bytes fixed and compare byte2=0 with byte2=`0x97`. The `TITLE+0x18318` and `+0x1831f` masks then have nonzero operands; prediction: at least one constructed camera/projected lane or FT4 UV field differs, while callback order, packet stride, and OT insertion remain the same. Falsifier: no such data change or any topology change. Falsifier for association: any missing role, unknown helper, changed callback sequence, corner mismatch, or incorrect command/OT/cursor result. This avoids treating coordinate equality as identity.

The final bounded run passes exactly three cdecl arguments to `TITLE+0x181e0`: resource pointer, object pointer, and `arg3=1` packet count. A prior four-argument harness attempt was discarded after the native loop read `arg3` and ran 256 iterations. Execute the two named contexts above with hash-pinned TITLE/HERC bytes in Unicorn. This is a bounded native producer experiment, not a claim about source identity, all TITLE modes, general world units, runtime gameplay visibility, or pixels.
