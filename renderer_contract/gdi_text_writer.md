The entry consumes three stack DWORDs: x at `[ESP+4]`, y at `[ESP+8]`, and a NUL-terminated ANSI message pointer at `[ESP+0x0c]`. Both epilogs use plain `RET`, with no callee cleanup, so the observed function shape is caller-cleaned and cdecl-like. The runtime caller and declared return type are unknown. The body increments one counter byte at VA `0x96e408`, masks its low three bits, adds ASCII `'0'`, and formats `(%c) %s ` into a 256-byte local buffer. It scans the result to NUL and passes the non-NUL byte count to TextOutA.

When mode byte `[0xBA020C]` is zero, the body calls USER32 `GetDC(NULL)` at RVA `0x64db`, calls GDI32 `TextOutA` at `0x650c`, then calls USER32 `ReleaseDC` at `0x651e`. TextOutA receives the HDC return, raw x/y, the formatted buffer, and its length. ReleaseDC receives the current HWND from `[0xBA0200]` plus the same local HDC. The acquisition uses literal NULL while release reads a global HWND; numerical inequality depends on that global being nonzero. Microsoft documents `GetDC(NULL)` as returning a DC for the entire screen; this does not establish that the game intended an overlay or that the call produced visible output in the tested environment. [GetDC documentation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdc).

When `[0xBA020C]` is nonzero, the function reads attached surface `[0x96e3ec]`. If nonzero, it calls that object’s vtable byte offset `+0x44` at `0x648b`, passing `this` and a pointer to a local HDC at entry `ESP-0x104`. It then calls TextOutA at `0x64b7`. Afterward it re-reads `[0x96e3ec]` and, if nonzero, calls vtable offset `+0x68` at `0x64ce` with the fresh surface pointer and the local HDC. The indirect targets are not invoked as DirectDraw implementations by this audit.

The acquisition HRESULT and TextOutA result are not tested. A null windowed HDC still reaches TextOutA and ReleaseDC. A failed surface acquisition still reaches TextOutA and the conditional surface release; if the provider does not write the output parameter, the local HDC remains uninitialized. If the attached-surface pointer is null, acquisition and release are skipped while TextOutA still consumes that local HDC. The surface pointer used for release is a fresh global read, not a cached acquisition receiver.

The only persistent native write in this span is the counter byte. The body has no absolute references to frame pointer `0xBA0210`, pitch `0xBA0214`, lock `0xBA01f0`, or dirty cell `0x43a590`; all four were guarded and remained unchanged in the five fixtures. This rules out direct indexed-frame writes by this helper. TextOutA is a separate HDC/surface writer.
