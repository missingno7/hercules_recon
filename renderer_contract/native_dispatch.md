# Bounded original-code renderer oracles

Both candidate tests use the shared CLI/runtime support in `candidates/renderer_bounded_oracle/oracle_common.py`. They require `--exe`; `--original-root`, `--deps`, `--analysis-deps`, and `--receipt` can be supplied when the default roots are unsuitable. The compact A710 and AC60 receipts are `report.json` and `ac60_report.json`; provenance and the two prediction/falsifier records are `provenance.json`, `prediction.json`, and `ac60_prediction.json` here. Each test maps the pinned HERCULES.EXE PE sections at image base `0x400000` in 32-bit Unicorn, keeps original code bytes unchanged, and stops at a hooked return sentinel. Unknown code, memory, or OS import endpoints fail.

Three finite nonnegative cases pass with `y + height <= 480`: `(5,224,7,3)` uses the original REP MOVSD/MOVSB path; `(127,478,3,2)` crosses the x=128 tile boundary and uses the original per-byte path; `(9,240,4,0)` writes no bytes. For every nonempty case, the observed PC-address-value stream equals the instruction-derived expected stream, including the `2*width` source stride and `0x100` row step. The entire mapped `.data` section is checked for writes outside pixel output and temporary gate cells, then restored byte-for-byte. BD80 runs exactly once per case; a nonzero synthetic callback pointer forces the original DWORD gate read while a zero gate skips the unmapped callback target.

The recorded y<512 address relation is `0x96e6e0 + row*0x100 + ((2*x&0x700)<<8) + (2*x&0xff)`, with `row=(y<256 ? 0 : 0x800)+(y&0xff)`. The first dynamic case corrected an inverted preliminary formula: y=224 writes at base + `0xE000`. The A710 span hash is `30bd84ea8724152e3bfb0e2c521650399913bcec115f1aef489768085981d0fe`; BD80 is `6a9578c5be0c980bc35b29642d3ac389e829a0c5666022353cb88c04f19db64f`. The original EXE hash is the pinned `587ae2e90fd2d1827dab6a2745340240e500846f974f718278e2a50199769c1d`.

The AC60 fixture executes one linked chain containing FT3, FT4, GT4, E1, F3, command 01, a variable sprite, a 0x40 gate, and NULL. It confirms native field staging at four real raster call entries and command-01 arguments at the actual A8F0 entry, then skips those callees with host register callbacks. Its F3 vector uses x=-7 and encoded y=0xF5, observing original store results `{left,top,right,bottom}={0,5,13,240}`. FT3 UV2 uses distinct U2=101 and V2=203: original stores write V2 to A909F4 and then overwrite it with U2. GT4 later RGB inputs use distinctive values which do not appear in native staging stores. The exact PCs, addresses, values, packet order, callsite returns, and fixture data are in `ac60_report.json`.

Both results are `BOUNDED_EQUIVALENT` only for the finite fixtures. They do not establish the full A710 callback domain, allocation or texture ownership extent, rasterizer pixels, A8F0 VRAM output, DirectDraw behavior, gameplay, source identity, `FUNCTION_MATCH`, or whole-module equality. A710 contains no CRT memcpy call; original string instructions and byte stores perform its copy. The official Unicorn wheel and DLL hashes, origin URLs, environment, and commands are in `provenance.json`.
