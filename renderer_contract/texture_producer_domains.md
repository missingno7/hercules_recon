# First-party texture-upload producer domains

The prior prediction was that ENG1's literal might be the only fixed high-y
startup upload and that its x range would stay below the reciprocal table. The
falsifier was a pinned ENG3 high-y rectangle plus a direct route to A710, or a
fixed x/y combination reaching the reciprocal-cell witness. The first half was
falsified: ENG3 has the same literal rectangle and calls the copied host slot
129 wrapper. The fixed startup rectangles still do not reach the witness.

Machine-readable package evidence and output hashes are in
[`evidence index`](evidence/upload_producer_domains.json).

ENG1's file-backed rectangle is at `ENG1.DLL` RVA `0x5DF00`, in the cold-start
path represented by `src/eng1/behavioral/cold_start_32b10.c` and
`evidence/eng1_cold_start_32b10.json`. That path allocates and loads `0x21000`
bytes, calls slot 129/A710 with `{x=0,y=512,width=128,height=512}`, then releases
the source after upload. ENG3's same rectangle is at RVA `0x39868`; the pinned
caller span `0x250AA..0x250D0` passes a loader-returned source pointer and the
rectangle through wrapper RVA `0x1FE30`, whose indirect host target is slot
129/A710 at RVA `0xA710`. The static receipt records exact code-span sizes and
SHA-256 identities, not instruction bytes or disassembly text:
[`original sites`](evidence/upload_producer_sites.json), generated by
[`tests/audit_upload_producers.py`](tests/audit_upload_producers.py).

For either literal rectangle, original A710 writes 128 KiB to the address
interval `[0xA6E6E0,0xA8E6E0)`, which spans two adjacent 64 KiB address pages at
the alternate base. The native finite fixture ran the unchanged original A710
and BD80 bodies with synthetic deterministic source bytes. It observed all
131072 output bytes and 32768 four-byte stores, matched the source byte for
byte, found only the output and the explicit callback/gate fixture cells changed
in the complete private `.data` image, checked the page/color/scratch and
reciprocal-cell witnesses unchanged, and restored the whole emulator-local
`.data` snapshot. BD80 ran once with its original notification gate disabled;
no callback endpoint was fabricated. Receipt:
[`native fixture`](evidence/native_cold_upload.json), runner:
[`tests/test_original_cold_upload.py`](tests/test_original_cold_upload.py).

The separately observed A710 high-y row expression is
`0x1000 + (y & 0x1FF)` for the exercised `y=512..1023` rectangle. With
`x=0..127`, each row copies 256 contiguous bytes. This is a write-address result,
not an allocation owner, whole-bank initialization, safe-read range, or bound
for other signed-WORD callback inputs. The address-only witness
`{x=284,y=514,byte-in-word=0}` evaluates to `0xA8E918`, the R[0] cell, but neither
fixed startup rectangle reaches it: their x range ends at word 127 and their
write interval ends `0x238` bytes before R[0].

[`tests/test_texture_high_y.c`](tests/test_texture_high_y.c) checks the bounded
high-y address vectors. The helper is defined in
[`hercules_textures.h`](hercules_textures.h) and
[`hercules_textures.c`](hercules_textures.c). It returns a 32-bit address expression
based at `HERC_TEX_MAP_BASE` and is
restricted to x words `0..1023`, y rows `512..1023`, and byte-in-word `0..1`.
The witness is only formula arithmetic; it is not evidence that a producer
supplies the witness rectangle.

Other producer domains remain open. ENG3's split uploader at RVAs
`0x7C8B/0x7CCC` derives one y from object state plus 512 and the other directly
from state; without a proven state range its alternate-page uptake is possible
but not established. ENG1/ENG3 descriptor uploaders copy rectangle words from
loaded resource records, whose values are not inspected. TITLE's input upload
uses a context-sourced y at offset `0x138`, with no writer or bound established
here. Fixed ENG1/ENG3 normal-band and TITLE rectangles, tile-group uploads, and
palette uploads do not supply evidence that these unresolved domains are
bounded. The direct-call scan is a Capstone linear sweep over the file-backed
ENG3 `.text`; its receipt explicitly excludes overlapping instruction streams,
computed calls, code outside that section, and resource/state runtime values.

## Reproduction

From PowerShell, use the checkout containing the public `scripts/pe.py` and
`renderer_contract` helpers. Original images are read-only inputs; all receipts
must stay under that checkout's `work` directory.

```powershell
$checkout = 'D:\Prog\hercules_recon\work\renderer_interface_repo'
$package = Join-Path $checkout 'renderer_contract'
$images = 'D:\Prog\hercules_recon\work\discs\pc_install'
$engineImages = 'D:\Prog\hercules_recon\assets\pc\HERCULES'
$python = 'C:\Users\jiriv\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
$env:PYTHONDONTWRITEBYTECODE = '1'
& $python -B (Join-Path $package 'tests\audit_upload_producers.py') --original-root $checkout --exe (Join-Path $images 'HERCULES.EXE') --image-dir $engineImages --output (Join-Path $checkout 'work\replay\upload_sites.json')
& $python -B (Join-Path $package 'tests\test_original_cold_upload.py') --original-root $checkout --exe (Join-Path $images 'HERCULES.EXE') --output (Join-Path $checkout 'work\replay\cold_upload.json')
```

The scripts pin the HERCULES/ENG1/ENG3/TITLE images and public helper identities.
The native runner uses public `renderer_contract/tests/oracle_common.py`,
`scripts/pe.py`, Unicorn 2.1.4, and its pinned DLL hash. The address helper test links against the shared texture implementation.
