## Geometry identity and precision

The selected original mesh has eight packed points and three emitted FT4 faces.
Winding preparation maps X to `64-X` in this case. The loop prefetches the next
packed point before B720 writes the current projected result. Retain the
preceding B6F0 identity and its scratch-slot address; assigning the most recent
resource read to the B720 result is incorrect. Face indices then connect those
point identities to packet corners and ordering-table placement.

The real-resource projection test preserves original signed-WORD inputs,
fixed-point transform narrowing and original screen WORD results in its
compatibility outputs. Its private coordinates use camera-space values, never
scaled screen WORDs. A separate synthetic discriminator has camera X values
1 and 2 that both produce native X=160 but private X=961.536 and 963.072.
That precision collision is not attributed to the shipped mesh.

The selected controlled resource context emits coordinates beyond 320x240.
This establishes numerical association, not on-screen coverage or a rendered
image. Resource bytes and large traces remain generated under ignored `work`;
public runners must read the original archive without changing it.

The preparation comparison passes 51 checks and feeds the unchanged source
emitter for 914 checks over the three archived cases. B810 writes camera XYZ
as WORDs at visit `+0x0C`; Z aliases depth `+0x10` before the signed shift by
two. This explains the observed `384 -> 1280 -> 320` case. Cold and warm cache
paths have separately compared callback sequences. Generated case headers now

## ENG3 bounds and selected resource

The allocator at `22790` owns the bounds pointer `4078C` and the per-entry
resource pointer table `40540`. Writer `204C0` uses 12-byte rows and writes
lower and wrapped lower-plus-extent at offsets +4/+8. Predicate `24A80` reads
a signed high WORD from object DWORD +0, shifts it by seven, zero-extends the
object WORD at +0x38 as the row index, then checks `[lower,upper)` with signed
DWORD endpoints. The physical meaning of those coordinate units remains open.

FOREST is an insufficient ENG3 resource identity: its count becomes negative
under `1AF10`. The archive's Cyclops entry gives count four and in-slice
pointers under the same original parser. In the isolated image fixture,
`22790` cannot complete because the preserved EXE allocator has no initialized
heap arena; `20190` reaches the row writer and then the missing `40540` state.
This candidate selection is not a live TITLE-to-level binding.

The C seam comparison separately proves normal and wrapped endpoint stores,
and rejects coordinates 9/20 for `[10,20)` while 10/19 reach the original
transform helper. That positive path faults at `24C49` through null `407B4`.
That null cell is table word5 (`407A0 + 0x14`), the known host sine-table
pointer. This earlier fixture initialized selected callback cells rather than
the complete native prefix. Its null-tail
result is a fixture boundary, not evidence of an unknown game service.
The new [depth fixture](fixtures/eng3_depth_accept/eng3_depth_accept.md) copies
all 250 words and reads the file-backed Q12 lookup directly. Coordinate 9
returns `-1` before transformation; coordinate 10 produces camera Z 640,
projected depth 160 and return zero using controlled zero-angle inputs and
three scale factors `[4096,4096,4096]`. These are scale operands, not a 3x3
matrix. No runtime lookup-table builder is required for this mapped fixture.
Unicorn read-hook metadata is not used as the operand value.
This is not reported as a successful visibility-to-emission path. No clipped
vertices, screen writes or broader-aspect policy are inferred. See
[bounded ENG3 source seam](fixtures/eng3_visibility_source/eng3_visibility_source.md).

## Composition and interception consequences

The connected state-only fixture locks the shared indexed view, applies E1,
processes a zero-height command-01 request, permits a synchronous callback to
rewrite the next link, reloads that link, and finishes the windowed surface
tail. Its `70C0(0xFF)` remap request skips the pixel loop because of the seeded
guard state. Controlled StretchDIBits/GdiFlush endpoints verify arguments and
order; neither original Windows drawing nor pixel equality is claimed.

The separate [rectangle frame fixture](fixtures/composition/raster/README.md)
adds actual indexed-pixel comparisons: source derives D420's axis-aligned,
1:1-UV rectangle and CAB0's transparent-zero loop. Both compilers match the
baseline's three writes and the shifted 3x2 case's six writes, followed by
remap request, unlock and controlled presentation. Asymmetric UV reaches the
original generic route and is explicitly unsupported by this source subset.
Pixel equality here concerns synthetic indexed buffers, not visible output.

An interception of slot89 must preserve these state changes, live-link reloads,
notifications and surface/present effects. A single entry snapshot cannot
replace the subsequently consumed mutable stream. Other texture, movie,
palette, desktop-DC text and mode writers remain independent routes. Their
order against a real gameplay frame is still open. Primitive family alone
does not identify a persistent world or UI layer.

The smallest supported deployment candidate remains an app-local DDRAW loader
with a stable selective callback-table clone and transparent forwarding.
Loader selection and renderer interception are separate boundaries. The
source-built controller adds tested observation machinery; it does not grant
display ownership or prove a safe original-game launch. Verified writable-path
and registry/profile isolation, windowed startup, module identity checks and
display restoration remain prerequisites for that experiment.

The [connected adapter fixture](fixtures/presentation_probe/postentry_adapter/README.md)
checks actual source-built module file hashes and the unchanged source-table
baseline. Its seven synthetic cases include identity/hash rejection, source
mutation, invalid signature and timeout cleanup. Callee-return observation
remains distinct from wrapper completion at a later caller-return marker.
Its original-host mode is blocked before process creation.

No GPU backend, SDL integration, gameplay rewrite, original-process launch or
new strict match is part of this checkpoint.
